# 降本与输出纪律 v2.3（2026-11-05，全员必读；v2.3.1 热修 2026-11-05）

> **v2.3.1 热修（复测后补丁）**：
> ① **格式预算≠条目上限**：本文件所有行数/字数预算只约束表述，不限制条目；任何有依据的发现都必须保留（建议级至少一行），不得因预算漏报、降级或改写成"待确认"；预算不够先压行内字数/统计，不删条目。
> ② **覆盖必须分「实判/引用」**：校验臂报告头写两栏——实判哪些 C/X（给结论）、引用哪些（仅参考他臂）；结构臂须对全部 C 给时间线/衔接扫读结论；不得只写"声称 27/27"。
> ③ **"待确认"只能是真不确定**：有依据但不确定严重度的，可标"建议·待确认"，但必须给依据与风险；不得用它替代建议级上报或规避条目。

> 依据：v1.4 实测成本 ¥3.781（超 B 预算 152%）。成本结构：**输出 69%／输入 21%／缓存 10%**。
> 结论：先压输出与无效调用；上下文/RAG 优先级低。本文件优先于各角色文件的输出格式（判据与只读红线不变）。

## 一、按需召唤矩阵（P0-3，硬规则）

| 角色/任务 | 何时召 | 不召的条件 |
|---|---|---|
| 01 内容校验 | 每轮首检/复核 | —（核心） |
| 02 结构校验 | 需要结构臂时；与 01 并行 | 只查事实/口径且用户只要内容臂时 |
| 03 参考建议 | R/S 清单已有 ≥1 条且用户要方案 | 无 R/S、或用户只要"有没有问题" |
| 04 修订 | 用户确认单勾选后 | 未勾选一律不召 |
| 06 规则包整理 | 建包、基准升版、规则包疑似漂移 | 基准未变时禁止重建/校包 |
| 07 规划 | 定稿档确需拆块（长文 > 1 万字或多卷） | 日常档整稿不拆；不必拆就不召 |
| M 误报降级 | **默认取消独立实例**：并入 03 同轮做（"这条我复核过，建议降为 X"） | 只有用户点名"魔鬼辩护"才单独召 |
| N 采样冗余 | 关键卷/定稿前，用户点头 | 默认不召 |
| 08 设定增补 | 主线闭环后用户主动要 | 默认不召 |

主控纪律：**同一实例不重复 spawn；同一问题不重复派单；wait_agent 超时只重试不重派。**

## 二、中间报告输出预算（P0-1 安全部分）

> v2.3.1：本节行数只为表述上限，不是条目上限；不得因预算漏报/降级，见顶部热修③。

- 角色中间报告一律"**结论表＋证据行号**"，不要复述基准原文、不要长篇分析：
  - 01/02：每条问题 ≤2 行（编号｜位置+原文≤25字｜类型｜依据行号｜等级）；报告 ≤40 行，明细入表。
  - 06：只给 C/X 索引表＋断言表/补丁清单＋待确认项，≤60 行。
  - 04：只给替换包（逐字）＋对照表，不给说明文。
  - M/03 的误报降级结论：每条一句话（维持/降级/理由≤20字）。
- **主控汇总**：每步回给用户 ≤20 行（结论、blocking、待勾选项、成本），不转发队友原文，只给"要点＋文件/段落位置"。
- 不压：blocking/承重条目的解释、依据出处、逐字替换文本、会改变判断的限定条件（见 §四）。

## 三、面向用户的建议：结构化双通道（小步试点）

03 的建议输出改为三段，**默认只展开第一段**：

1. **决策摘要（用户看）**：每条建议最小充分集——编号｜位置（行号+原文≤25字）｜问题类型｜依据（总纲/卡/规则包行号）｜影响（一句人话）｜推荐档（最小/折中/较大）｜风险一句。
2. **三档对比表**：每档只写"改动量/风险/效果"各一短句；推荐档标★。
3. **逐字替换包（给 04，折叠）**：每处一行「原文→替换」，供 04 定点执行；用户可不看。

- 用户说"展开 #编号"再展开全文（主控从详情文件/段落读取，不重新生成）。
- 04 只按第 3 段逐字文本执行；01 复核逐字核对。
- 试点验收：同稿 A/B（完整版 vs 结构化版）比较采纳率/理解偏差/修订准确率；不达标回退。

## 四、压缩红线（不许压）

- 原文锚点（≥5 字定位）、问题编号、依据出处行号；
- 承重/blocking 条目的解释与风险；
- 三档方案差异点；
- 逐字替换文本；
- 会改变判断的限定条件（如"若作者本意不同则不判错"）。
- 一句话原则：**宁可多写一句解释，不可少给一处可核对信息。**

## 五、推理档位建议（P0-2）

- 若宿主支持每角色推理档位：01/02 用高档（关键判定）；03/04/06 用中档；07/08 用低档；不要全员 max。
- 宿主不支持时（如 DSH Agent Teams 当前 spawn 不暴露档位）：用输出纪律替代——**不写推理过程、不重复复述、直接给结论+依据**；长思考只在真正需要权衡的条目上用。
- 可选增强：安装 `dsh-subagent-director` 之类插件做按角色模型/档位分配（非必需）。

## 六、缓存与工具集（P2，可选）

- 静态前缀放前、动态信息放后：角色规则＋本文件＋基准索引摘要为静态段；项目路径/日期/任务编号放后面。
- 同轮多角色共用同一份"基准切片文件"（主控预切），避免各自整读；不要给只读角色写文件/终端类工具（平台支持时裁剪工具集）。
- 主控记录：每步 token/成本、首请求缓存命中（若平台可观测）。

## 七、成本验收（复测口径）

- 目标：同项目 v1.4 稿复测，总成本 **≤¥2.0（较 v2.2 -47%），冲刺 ≤¥1.7**；输出 token 降 40%+。
- 质量门：blocking=0；有效问题数不降；误报不升；用户理解抽检通过。
- 任一项不达标：回滚对应改动，只保留已验证项。
